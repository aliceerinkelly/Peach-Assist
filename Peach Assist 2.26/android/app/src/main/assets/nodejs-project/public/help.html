The Peach Assist manual

A working guide to the messenger you are looking at: how to sign in, talk to people, keep track of work, and run the thing when you are the one in charge. Everything below describes what the server actually does, so you can hand this page to a new colleague on their first morning.

Type in the search box at the top and the page narrows to the sections that mention your words. Clear the box to see everything again.

Before you begin

What you need

Nobody should start an install and meet the blocker halfway through, so here is the whole list at the front. Three groups: what the server cannot work without, what only matters if it is reachable from the internet, and what people wrongly believe they need.

Required - nothing works without these

  • A Windows 10 or 11 computer that stays on. It is the host, not a laptop that sleeps. While it is off, nobody can reach the messenger.
  • Administrator rights on that machine. Enough to install software and let it through the Windows firewall.
  • One router, under your control. You can log into it and find its UPnP setting.
  • UPnP switched on. The router's permission slip for opening a port. The setup page's second light proves it.
  • A public address. If the router reports a private address while the internet sees a different one, you are behind carrier-grade NAT: no forwarding will work, and the honest choices are LAN-only mode or a different connection.
  • A free No-IP account, if it will be used from the internet. Two minutes to sign up, and the server keeps the name pointing at the right address as that address changes.
  • Somewhere to keep backups. Any external drive or cloud folder you already use. The database is a single file; see chapter 21.

Required only for internet access

  • Port 80 or 443 reachable from outside. One of the two almost always is. If the ISP blocks both, a certificate cannot be issued and the install stays LAN-only.
  • A name that keeps up with the address. Home addresses change. A name that stops updating turns yesterday's working link into today's dead one.
  • A phone on mobile data, for the test. Testing from the same Wi-Fi proves nothing about the outside world.

Not required

  • A VPN. Not needed in the normal setup.
  • A static IP address.
  • A purchased domain name. It buys a prettier address and nothing else.
  • A server, a VPS, or cloud hosting.
  • Any account with us.
  • Forwarding a port by hand. The server asks the router over UPnP.
Outside the supported setup. Two routers in a row, carrier-grade NAT, or a firewall somebody else controls. The app will name the problem, but it cannot fix a network it does not own. LAN-only mode is the supported answer for those connections.

The five lights

The setup page checks the same five things in this order, and each one says what to fix rather than simply going red: a public address, the port is open, the name points here, reachable from outside, and a trusted certificate. Change something on the router, then press Check my network again.

Chapter 1

1.What this manual is

The messenger is a private chat server for one organisation. It runs on a computer in your office (or on one small rented machine) and everybody reaches it through a browser â€” there is nothing to install on a phone or laptop.

It has three kinds of people:

  • Colleagues â€” people with a username and password. They chat with each other, share files, keep notes and tasks, book meetings and ask for time off.
  • Clients â€” outside people you invite with a one-off link. A client only ever sees their own conversation with you, never the rest of the server.
  • Administrators â€” colleagues with an extra panel where they create accounts, reset passwords, set policy and load or unload whole features.

Data lives in a single folder on the server machine: a database file plus an uploads folder. Nothing is sent to a third party. That also means backups are your job â€” see chapter 21.

Teaching tip. Give a new colleague this page and three tasks: send a direct message, drop a file in the Drive, and request a day off. Those three cover most of the app.

Chapter 2

2.Signing in

Open the address your administrator gave you â€” usually http:// followed by the server's address and :3000 â€” and sign in with your username (or email address) and password.

If you forget the password

There is no self-service reset, on purpose: the server has no way to send mail to the outside world by default. Ask an administrator, who can set a new password from the administration panel without losing any of your history.

Sign-in links

The login page can also email a one-time link. While the server is being set up, that link is printed into the server's console window instead of being sent â€” useful on the first day, not something to rely on afterwards.

Two-factor codes

An administrator can turn on two-factor sign-in for everybody, or you can enrol yourself from your own settings. You add the six-digit code to any authenticator app once, and after that you type the current code after your password. If you lose the phone, an administrator can clear the secret for you.

Five wrong passwords in a row will slow further attempts down. Wait a minute rather than hammering the button.

Chapter 3

3.Finding your way round

The window has three parts.

The railThe narrow strip of icons on the left edge. Each icon opens one tool: search, archive, notes, reminders, tasks, calendar, time off, drive, mail and â€” for administrators â€” the helpdesk.
The listYour chats in the middle: direct conversations, groups, shared rooms and clients. Tabs at the top switch between everything, unread, archived and the different spaces.
The conversationThe message thread on the right, with the composer at the bottom and the details of the chat in the header.

Not every rail icon is present on every server. An administrator can load or unload whole features, and the icons follow: if a tool is unloaded it simply is not there, for everybody. That is not a fault â€” see chapter 19.

The space switch at the top of the list separates work conversations from the social side. Administrators decide which space a room belongs to.

There is no built-in voice note or dictation here. To speak instead of type, use the microphone key on your keyboard or phone keypad: it writes ordinary text into the box, and nothing is recorded or uploaded by Peach Assist.

Chapter 4

4.Sending messages

Type in the box at the bottom of a conversation and press Enter to send. Shift+Enter starts a new line. Messages appear instantly for everybody in the conversation, and a small tick tells you when the server has stored yours.

Editing and deleting

Point at one of your own messages: the menu offers edit and delete. Editing marks the message as edited so nobody is misled about what changed. Deleting hides the message for everyone; the row stays in the database only long enough for the deletion to reach every open window.

Replies, mentions and acknowledgements

You can quote a message to keep a long thread readable, and mention a colleague so their name stands out. Messages can also ask people to acknowledge that they have read something â€” useful for announcements where "I didn't see it" is not a good excuse.

Polls

A poll is a message with options. Everybody in the conversation votes once and sees the tally; the person who asked can close it when the decision is made.

Canned replies

The server keeps a list of stock replies. Type a slash to see the ones that match, then pick one to drop it into the composer before sending. These are ordinary messages once sent â€” you can edit them.

Off the record. With the off-the-record switch on, a message is relayed to the people in the conversation and then thrown away: it is not stored and will not appear in search. Only use it when the other person understands that the history disappears.

Chapter 5

5.Files, pictures and voice notes

The paperclip adds an attachment. Pictures show a preview; everything else shows a name, a size and a download button. Attachments belong to the message that carried them, so deleting the message removes the file too.

Voice notes are recorded in the browser and sent like any other attachment, with a duration shown next to them.

Administrators can switch attachments off for an individual person. If the paperclip has disappeared, that is why â€” ask, don't guess.

Size limits are set by the server, and every upload counts against the disk. If an upload refuses, check the size first, then ask whether the server's disk is full.

Chapter 6

6.Direct chats, groups and rooms

Direct chats

Click a colleague in the list to open a private conversation. Only the two of you can read it, and it is created the first time either of you writes. Whether colleagues may start chats across departments is a policy an administrator controls.

Groups

A group is a private conversation with a name and a chosen list of colleagues. You create one from the list header, pick the people, and from then on everybody in it sees the same thread. Members can add or remove others; leaving is done from the group's menu, and the group disappears from your list when you do.

Shared rooms

A room is an open conversation for the organisation â€” think "Support" or "Lobby". Rooms appear in the list for everyone in the space, and they can be linked to the outside with a guest link (next chapter).

Clients

A client is an outside person tied to one conversation. Their messages land in your list like anybody else's, but they never see other clients, rooms or colleagues. Revoking their link ends their access without deleting the history you need.

Chapter 7

7.Shared rooms and guest links

Every shared room has a public address of its own. Send it to somebody outside the organisation, they open it in a browser, type a display name, and they are in â€” no account, no password.

  1. Open the room and choose the link button in its header.
  2. Copy the address. It looks like /r/ followed by a long identifier.
  3. Send it however you like. Guests can read and write in that room only.

Guest names are not verified, so treat a room link as "anyone with this address can walk in". Don't post confidential material in a room whose link has been shared widely. Deleting the room removes the link and the messages in it.

If the server is behind a router, links only work inside the network unless the administrator has set a public address. The address used in links is shown in the administration panel, so there is one place to check when a link "doesn't work from home".

Chapter 8

8.Status and availability

Your name in the list carries a dot and a word: online, away, busy, or offline. Set it from your own menu, with an optional line of text â€” "at the dentist until 3" saves everybody a question.

You can also leave an automatic reply. When somebody writes to you, they get that line once an hour instead of silence. It is not a chatbot: it is one sentence, sent on your behalf, and it stops when you clear it.

Presence is honest in one direction: closing the laptop does not instantly say "offline", but the server notices when no device is connected and shows you as offline the next time the list is drawn.

Chapter 9

9.Search and the archive

The magnifier searches message text, names and files across the conversations you are allowed to read. You can narrow by date and by client, and a hit opens the conversation at that point.

  • Search is for your eyes: it never returns a conversation you could not already open.
  • Off-the-record messages are not in the index, because they are not stored.
  • If old messages are missing, check retention in chapter 20 â€” the server may be deleting history on a schedule.

The archive

Archiving takes a chat out of the main list without deleting anything. The archive tab shows what you have put away; open the chat and unarchive it to bring it back. New messages still arrive in an archived chat â€” archiving tidies, it does not mute.

Chapter 10

10.Sticky notes and reminders

Sticky notes are short private notes kept on the server so they follow you between computers. Nobody else can read them. Use them for the phone number you always lose, not for passwords.

Reminders are one-off nudges: a line of text and a time. When the time passes, the rail icon shows a dot and the reminder is waiting when you open it. Mark it done and it goes away. Reminders are per person and are not sent to anybody else.

Chapter 11

11.Tasks

A task is a small piece of work with an optional owner, due date, priority and a link to a conversation. Tasks appear in three places depending on their scope:

  • Private â€” only you see it.
  • Team â€” everybody in the team can see it.
  • Room â€” it belongs to a room and shows up for the people in that room.

Assigning a task sends the owner a quiet notice rather than a message in the chat. Overdue tasks turn red, and the rail icon shows how many are waiting. Marking one done keeps it in the list until you filter it away â€” the record stays, which is what makes the reports reliable.

Chapter 12

12.Calendar and meetings

The calendar shows a day or a week at a time, with your meetings, the tasks that fall due, and (when the time-off feature is loaded) who is away.

Booking a meeting

  1. Choose New meeting, give it a title, a start and an end.
  2. Add a location or a link if people need one.
  3. Invite colleagues. They see the invitation and answer yes, no or maybe.

Meetings you organise look different from meetings you were invited to, so a glance tells you who is waiting on whom. Cancelling tells everybody it is off; it does not silently remove it.

Putting the calendar in your phone

The calendar can be published as a private address that Google Calendar, Outlook or Apple Calendar can subscribe to. Treat that address like a password: anyone who has it can read your schedule. There is also a one-off download for a single file you can import elsewhere.

Chapter 13

13.Time off and holidays

Time off is its own feature: an administrator can unload it without touching the calendar, in which case the time-off icon and the button inside the calendar disappear.

To ask for leave, open Time off, pick the type (annual, sick, personal or unpaid), the first and last day, and add a short note. The request goes to the administrators, who approve or decline it. You can see the state of every request you have made, and cancel one that has not been decided.

Public holidays are maintained by an administrator. They appear in the calendar and count against nothing â€” they are there so nobody books a meeting on a bank holiday.

Approvals are not automatic. A request sitting at "pending" is waiting for a person, not the software.

Chapter 14

14.Drive

The Drive is the shared filing cabinet. Files live in folders, can be replaced with a new version (the old one is kept), and can be shared with named colleagues or with everybody.

  • Uploading a file with the same name as an existing one offers to add a version instead of a duplicate.
  • Version history lets you download an earlier copy when the new one turns out to be wrong.
  • Quota is set by the administrator, per person. The panel shows how much is in use.
  • Sharing is explicit: a file nobody shared is yours alone, even in a shared folder.

Files sent as chat attachments are separate from the Drive. Attachments belong to their message; Drive files have a home and a history.

Chapter 15

15.Mail

Mail is internal correspondence that does not belong in a chat: longer, with a subject, and with attachments that people expect to find again. It stays on your server â€” the messenger does not deliver to outside email addresses.

Each message can go to one colleague or several, can be replied to, and can be moved to the bin. Unread mail puts a dot on the rail icon. Deleting mail removes it from your view; the other people's copies are theirs.

Use chat for a conversation, mail for a record. If somebody will search for it in three months, mail is usually the better home.

Chapter 16

16.Helpdesk

The helpdesk collects support tickets from inside the organisation. Colleagues write what is wrong, administrators see a queue, reply, and close the ticket when the problem is solved. The rail icon only exists for administrators and only when the feature is loaded.

An open ticket count on the icon is a gentle reminder that somebody is waiting. Replying from the ticket keeps the whole exchange in one place, which is more useful later than a chat that scrolled away.

Chapter 17

17.The administration panel

Administrators get a second panel, opened from their own menu. It is deliberately separate from the messenger: nothing here is visible to ordinary colleagues, and nothing in the messenger can change these settings.

People

Create colleagues, set their username, display name, role and department, reset a password, disable an account, or remove one. Disabling is usually better than deleting: the history stays readable and the person can come back. Per-person switches control whether somebody may send files, use off-the-record mode, or use the Drive.

Departments

Departments group people for the chat policy ("colleagues in my department only") and for reports. Removing a department unassigns its people rather than deleting them.

Clients and links

Invite an outside client, see whether their link has been used, and revoke it when the work is done. A revoked link stops working immediately; the conversation and its files remain for your records.

Rooms

Create shared rooms, copy their guest links and delete rooms that are no longer wanted. Deleting a room deletes its messages â€” that is the one destructive button in this area, and it asks first.

Server settings

Here you set the address used in links and emails, the messaging policy, retention, the Drive quota, whether off-the-record messages are allowed at all, whether two-factor sign-in is required, and which features are loaded (next chapter). Every change is written to the audit log with your name and the time.

Audit log

A running record of who changed what: sign-ins, password resets, permission changes, feature switches, deletions. When something surprising happens, this is the first place to look, and it is the reason the panel is separate from the chat.

Reports and tokens

Reports summarise working hours and chat activity without exposing message text you could not already read. API tokens let another program talk to the server on your behalf; treat a token exactly like a password, and revoke it when the program stops using it.

Chapter 18

18.Loaded features (modules)

Each tool on the rail â€” search, archive, notes, reminders, tasks, the wall, calendar, time off, Drive, mail and the helpdesk â€” is a module. An administrator can load or unload any of them from the server settings.

Unloading a module does three things at once:

  1. The rail icon disappears for everybody, including administrators.
  2. Any open window belonging to it closes.
  3. The server stops answering that feature's requests, as if it had never been installed.

Nothing is deleted. Loading the module again brings the icon back with every note, task, meeting and file exactly as it was. Chat itself is not a module: it is always on, because without it there is no messenger.

Why unload? A small team may not want a helpdesk or a Drive in the way. Unloading keeps the interface honest about what this installation is for, without turning anything off permanently.

Chapter 19

19.Privacy and retention

Everything is stored on the server you are looking at: the database, the uploaded files, and the audit log. There is no cloud copy unless an administrator makes one.

  • Who can read what: direct chats are for the two people in them; groups for their members; rooms for everybody in the space and anyone holding a guest link. Administrators can see what the server holds, which is worth saying out loud to new colleagues.
  • Off the record messages are relayed and dropped: no row in the database, no search hit, no backup copy from that moment on.
  • Retention can delete chat history after a chosen number of days. When it is on, older messages disappear on a schedule; the retention run time is shown in the panel.
  • Attachments follow their messages. Deleting a conversation's messages removes its files too.
If your organisation has a legal reason to keep or to erase conversations, decide the retention setting before people start using the server, and write the decision down.

Chapter 20

20.Looking after the server

The server is a normal program on a normal computer. Three small scripts in its folder do the everyday work:

startStarts the server in a console window and opens the port. Leave the window open; closing it stops the messenger.
stopStops the server cleanly so the database is not left mid-write.
buildRecompiles after an update. Run it, then start again.

Backups

Stop the server, copy the whole folder (or at least the data folder with the database and uploads), and keep the copy somewhere else. A backup on the same disk is not a backup. Do this before any update, and on a schedule you can keep.

Updates

Stop, copy, update the files, build, start, and open the login page to check the health of the server. If something is wrong, the copy you just made is the way back.

Write the server's address, the administrator username and where backups live on a piece of paper in the office. When the person who set it up is on holiday, that note is the difference between an afternoon and a week.

Chapter 21

21.Troubleshooting

Nobody can open the page

Check the server window is still open and the address is right. On the server machine itself, http://localhost:3000 should answer; if that works but other computers cannot connect, it is the network or a firewall, not the messenger.

A link works inside but not outside

Guest links use the address in the server settings. If that is a local network address, people outside cannot reach it, and no amount of re-sending the link will help. Ask the administrator to set the public address.

A rail icon has vanished

Either the feature was unloaded (chapter 19) or your account is not allowed to use it. Both are decisions somebody made; neither is a bug.

Messages look stuck

The window keeps a live connection to the server. If it drops â€” a laptop lid, a flaky network â€” the page reconnects on its own. Reloading the page is safe and never loses messages that reached the server.

An upload refuses

Too large, the disk is full, or attachments are switched off for you. The message says which; if it does not, ask.

The calendar is missing meetings

Check the day or week you are looking at before assuming data is gone, then check the meeting's invitations. A meeting you declined is still shown, marked declined.

Chapter 22

22.Handy habits

  • Enter sends, Shift+Enter makes a new line, Esc closes the window in front of you.
  • Type / in the composer to reach your canned replies.
  • Archive a chat the moment it stops needing attention; the archive is easier to search than a crowded list.
  • Put the deadline in a task, not in a message. Messages scroll, tasks do not.
  • When a conversation turns into a decision, write the decision in a mail or a note. Future-you reads records, not threads.
  • Name files the way you would search for them, and let the Drive keep the versions.
