Server

Maintenance

Hang up (HUP): reload the server's settings and push the current state to every open window — modules, commands, policies and the address used in links. Nobody is disconnected and nothing is lost. Startup-only changes (a new port, a rebuilt dist) still need the machine's own stop / start scripts.

Network HUP: re-apply the public path on its own — release or create the router rule, check the VPN port again, refresh the public address and the dynamic DNS entry. Open chats stay connected. If the new choice would move the listening port, it says a restart is needed instead of quietly doing nothing.

Setup again: re-run the first-run questions (personal or business, purpose, which parts to run). It needs an administrator signed in, and it only changes wording, modules and the default colour.

Setup again

Restart: stops the server and starts it again straight away, picking up anything that is only read at startup (a port, a certificate). On the phone the app brings it back on its own — nothing to tap on the device.

Clean copy: builds a downloadable package of the program with a fresh database — one account, admin / peach123 — and nothing of yours in it: no users, no messages, no hostname. It refuses to build if the database inside is not exactly that.

Download it

App update: paste the address of a newer APK (the little share on the computer, or any web address the phone can reach). The app downloads it, reads the version inside the file, and hands it to Android's installer — that replaces the app in place, keeping every message, account and setting.

This app: —

Port

Leave it empty to let the server decide: the port ProtonVPN forwards when the tunnel offers one, otherwise 3000. A number set here is used the next time the server starts — use the machine's stop and start scripts, since a running listener cannot move.

Dynamic DNS

Keeps a name pointing at this server, so invitation and sign-in links survive a new address from your ISP or VPN. Leave Public address below empty and links will use this name plus the port above; fill that in only if something else sits in front of the server.

Other: any provider that gives you an update address works. Paste that address in the field below with {host} and {ip} where the name and address go, for example https://example.net/update?host={host}&ip={ip}, and put the provider's username and password in the two fields beside it.

No-IP: the account login is no longer accepted for updates. On the DNS Records page open your hostname, enable Dynamic DNS and generate a DDNS key; paste that key's username and password here. The hostname can be your own name, or all.ddnskey.com to cover every name on the key.

Modules

Load or unload a whole feature. Unloaded modules take their rail icon away from everyone and their endpoints answer as if they were not installed. Nothing is deleted: loading the module again brings its data straight back.

Messaging policy

When this is off, nobody can send a message that is not saved. Client threads are always logged either way.

Call relay (TURN)

Calls connect directly when the two devices can reach each other. On mobile data that is often impossible, so a relay carries the call instead. Create a TURN key in Cloudflare (Realtime \u2192 TURN keys), then paste its ID and API token here. Both stay on this server; the browser only ever receives short-lived credentials. The free allowance is 1 TB a month.

Work hours

Outside these hours every page shows a short \u201cwe\u2019re closed\u201d note with the hours you set here, and the phone lets its CPU sleep instead of holding it awake \u2014 that is what stops it running hot in a pocket. The server keeps listening, so nothing that is sent is lost.

Peach Drive

Room drives are shared and are not counted against anyone's quota. Existing files above a lowered limit are kept; new uploads stop.

REST API keys

A key acts as you and can read your chats and send messages. Treat it like a password: it is shown once, and revoking it stops it at once.
